# requirements/

Generated, hash-pinned per-service requirements. **Files in this directory are
auto-generated by `bin/upgrade_packages.py` from `lib/*/requirements.in` and
`svc/*/requirements.in`** — do not edit them by hand.

## Generating

```bash
.venv/bin/python bin/upgrade_packages.py
```

This produces one `<service>.txt` per service plus `constraints.txt` and
`monorepo.txt`. The CI workflows (`.github/workflows/build_and_push_*.yml`)
generate the relevant file inline before each Docker build, so you don't need
to commit them. They are intentionally `.gitignore`d.

## Local Docker builds

`docker/service.Dockerfile` reads `requirements/<service>.txt`. If you build
locally without first running `bin/upgrade_packages.py`, the build will fail
with `requirements/<service>.txt: No such file or directory`. Run the
generator first.
